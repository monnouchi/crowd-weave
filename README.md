# 雑踏突破

公開準備中のブラウザゲームです。日本語タイトルは「雑踏突破」に決定しています。英語表記候補は Crowd Weave です。リポジトリ名変更の確認後に英語表記と公開予定URLを合わせます。

駅を行き交う人の目的と流れを読んで、北口のカフェ前で待つ人のもとへ向かうブラウザゲームです。自動で前へ歩き、左右の操作でよけ、両押しで立ち止まります。プレイヤーは画面の同じ位置に表示され、駅と人が移動に合わせてスクロールします。

全5ステージ（朝の改札 → ホームへ向かう人 → 乗り換えの時間 → 夕方の改札 → 混雑する駅）。歩行者は12、20、30、35、40人と増え、基準速度も上がります。接触するとタイムに2秒加算され、0.35秒足が止まり、1.4秒間は再接触の加算を防ぎます。接触した通行人だけが約0.7秒立ち止まってこちらを向き、「！」を出してから元の目的地・歩き方へ戻ります。同じ人に触れ続ける接触は1回だけ数え、離れてから再び触れると次の接触になります。加算は従来の1.4秒の猶予でも制限し、押したり傷つけたりする操作はありません。各ステージの目的・台詞・相手の服色はデータで切り替えられます。今回は全ステージが友好的な待ち合わせで、迷子の子どもの物語などは今後の候補です。各ステージの到着タイムと接触回数、最後に全ステージの合計を表示します。

## 起動と操作

Python 3 があれば、リポジトリで `python3 -m http.server 4175 --bind 127.0.0.1` を実行して http://localhost:4175 を開きます。Node.js がある場合は `npm start` でも起動できます。インストールは不要です。

- PC：左右矢印キーまたは A / D。Enterで開始・次のステージ・最終結果から再挑戦・停止中の再開。Escapeで停止。Enterの長押しでは連続して進みません。プレイ中のEnterはゲームをリセットしません。Tabでボタンを選び、Spaceでも操作できます。
- スマホ：左右ボタンを押して横移動。左右同時押しで前進・横移動が停止し、片方を離すと残った方向への移動と前進を再開します。
- ブレーキ中も周囲の人は歩き続けます。一時停止は人と時計も止めます。
- 「やり直す」で現在のステージを最初から開始。最終結果から最初のステージへ再挑戦できます。
- タブを隠す・ウィンドウのフォーカスを失うと自動で一時停止します。戻ったら「散歩をつづける」で再開します。

## 駅の歩行者

全員が改札・北口・ホーム入口のいずれかを出発点と目的地に持ちます。同方向、対向、斜めに横断する移動が混ざり、初期位置・速度・到着と再入場の時刻はそろいません。初期配置はすでに駅を歩いている状態です。

各人には一貫した急ぎ具合、希望速度、他人との距離、譲る強さ、立ち止まる習慣があります。急ぐ人は直接目的地へ、案内を読む人は側面の案内板で短く停止し、待ち合わせする人は待合で数秒待ってから進みます。向きと歩幅、速度、よけ方、停止によって違いが見えます。毎フレームのランダムな揺れはありません。

近い相手を見て減速と右側への回避を行い、速度への局所的な制約で体の重なりを防ぎます。止まっている人を押し動かしません。駅の外へ出た枠は、少し間をあけて外側の入口から次の通行人に再利用します。表示中の位置を飛ばして戻す処理はありません。入口が混んでいる間は新しい人を待たせます。カフェ前の到着エリアでは中立の待ち合わせ相手が待ち、近づくと「こっちだよ！」の吹き出しが表示されます。吹き出しは通行エリアより上に置き、歩行者の進路を隠しません。この相手は通行人と別に扱い、接触ペナルティはありません。到着すると合流の結果を表示します。

## 開発とテスト

Canvas / CSS / JavaScript のみ。ゲーム用の外部依存パッケージ、外部通信、素材のダウンロードはありません。Node.js 18以上で、インストールなしに実行できます。

```sh
npm test
npm run build:pages
```

29件のテストで、移動・衝突・停止・目的地、群衆の再現性と個性、安全な初期配置、回避と停止、全ステージと追加配置での接触ゼロの経路、入力解除、公開用ファイルの限定とプロジェクト用URLを検証します。実ブラウザではタッチの同時押し・片方の解除、ステージ遷移・最終結果・歩行者の動きを確認しています。実際の端末でのタブ切替とスマホの操作感は、継続して確認する対象です。

- `crowd.js`：目的地と個性、シード付き配置、歩行・回避・停止。
- `logic.js`：ステージ、プレイヤーの移動・接触・ゴール・時計。
- `input.js`：独立した入力元を扱う2ボタン状態。
- `game.js`：ブラウザの入力接続と描画。
- `pose.js`：実際の横移動から頭・肩の小さな傾きを計算。プレイヤーの画面位置と当たり判定は変えません。停止・両押し・壁際で正面へ戻り、動きを減らす設定では傾きを止めます。
- `branding.js`：画面タイトル「雑踏突破」。英語表記はリポジトリ名変更の確認待ちです。
- `scripts/build-pages.js`：公開用ファイルのみを `_site/` に集めます。

静的な相対パスを使うため、GitHub Pagesの `/crowd-weave/` 配下でもCSS・モジュール・LICENSEが読み込まれます。

## GitHub Pagesへの公開手順

ソースコードのリポジトリは `monnouchi/crowd-weave` です。Pages設定と公開は所有者が行います。手動ワークフローは設定後に実行できます。

1. `npm test` と `npm run build:pages` を確認し、公開対象のソースをmainへcommit・pushします。
2. GitHubの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定します。
3. Actions → **Publish GitHub Pages** → Run workflow で **main** を選び、手動で開始します。
4. 成功後、上の予定URLで操作・ステージ・ライセンスリンクを確認します。

ワークフローは手動起動のみです。mainへのpushだけでは公開されません。テストに成功した後、`_site/` をアップロードしてPagesへ配置します。GitHub公式ActionsはコミットSHAに固定し、Pages書き込み権限は配置ジョブに限定しています。[GitHubの公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)に沿った構成です。

サイトに含めるのは `index.html`、`style.css`、`game.js`、`crowd.js`、`input.js`、`logic.js`、`branding.js`、`pose.js`、`sound.js`、`share.js`、`og.png`、`LICENSE`、`.nojekyll` の13ファイルです。リポジトリ全体をアップロードしません。検証画像・ログ・ローカル確認用スクリプト・環境ファイル・秘密鍵・生成済み `_site/` はGit対象から除外しています。

固定の駅経路と局所的な回避を使う試作です。駅全体の経路探索、ランキング、記録保存はありません。

BGMと接触・ブレーキ・到着の効果音はWeb Audioで合成したオリジナル音です。最初の操作で音が有効になり、「音」ボタンでミュートを切り替えます。背景へ移ると停止し、再開操作で復帰します。歩行者の足の振幅を抑え、個体ごとの位相差をつけています。

通路の人流は縦方向を中心に設定しています（生成パターンは同方向5人・逆方向4人・横断1人）。横断はホーム側入口付近に限定し、各人の目的地は維持します。この比率はゲーム用の設計値です。

案内板前では初期状態から数秒の滞在が見え、右脇のトイレ前では3人が入口へ向き、先頭が出た後に順番に進みます。急ぐ人・慎重な人・通常歩行の速度差と局所的な加減速があります。子供と同行者は同じ掲示を目的地にした短い寄り道をし、子供は緩やかな速度変化、同行者との距離に応じた減速をします。年齢ですべての歩き方を決める設計ではありません。

最終結果で合計タイム・接触回数・ゲームURL入りの画像を共有できます。対応端末は標準共有メニューを開き、それ以外ではPNG保存と文章コピーを使えます。SNSへの自動投稿や画像の外部送信は行いません。

待ち合わせ場所の先にも北口コンコース・ベンチ・奥の通行人を描画し、到着点を駅の途中に見せています。奥の通行人はコース外の背景です。荷物を持つ駅利用者も描き分けています。プレイヤーのスーツケース付き高難度モードは含めていません。

OGPは静的HTMLのメタデータと1200×630のPNGです。実際のゲーム描画を使い、JavaScriptなしでタイトル・紹介文・画像URLを取得できます。Pages公開前はSNS側から画像を取得できません。
