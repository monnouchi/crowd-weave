# 雑踏突破

人混みを避けながら、仲間全員をライブ最前列へ連れていくブラウザゲームです。日本語タイトルは「雑踏突破」、英語名は Crowd Weave です。

街や施設を行き交う人の目的と流れを読んで、各ステージで異なる場所と目的に向かうブラウザゲームです。自動で前へ歩き、左右の操作でよけ、両押しで立ち止まります。プレイヤーは画面の同じ位置に表示され、街・施設と人が移動に合わせてスクロールします。

全5ステージで、自宅から住宅街・最寄り駅・駅カフェ・会場前・ライブ会場内へ進みます。歩行者は6、12、20、30、40人と増えます。速度や待機・流れも場所に合わせて変わり、最終会場は密度が高く、ゆっくり進む観客が中心です。接触するとタイムに2秒加算され、0.35秒足が止まり、1.4秒間は再接触の加算を防ぎます。接触した通行人だけが約0.7秒立ち止まってこちらを向き、「！」を出してから元の目的地・歩き方へ戻ります。同じ人に触れ続ける接触は1回だけ数え、離れてから再び触れると次の接触になります。加算は従来の1.4秒の猶予でも制限し、押したり傷つけたりする操作はありません。各ステージの目的・台詞・相手の服色はデータで切り替えられます。友だちと合流してライブ会場へ向かう物語です。各ステージの到着タイムと接触回数、最後に全ステージの合計を表示します。

## 起動と操作

Python 3 があれば、リポジトリで `python3 -m http.server 4175 --bind 127.0.0.1` を実行して http://localhost:4175 を開きます。Node.js がある場合は `npm start` でも起動できます。インストールは不要です。

- PC：左右矢印キーまたは A / D。Enterで開始・次のステージ・最終結果から再挑戦・停止中の再開。Escapeで停止。Enterの長押しでは連続して進みません。プレイ中のEnterはゲームをリセットしません。Tabでボタンを選び、Spaceでも操作できます。
- スマホ：左右ボタンを押して横移動。左右同時押しで前進・横移動が停止し、片方を離すと残った方向への移動と前進を再開します。
- ブレーキ中も周囲の人は歩き続けます。一時停止は人と時計も止めます。
- 「やり直す」で現在のステージを最初から開始。最終結果から最初のステージへ再挑戦できます。
- タブを隠す・ウィンドウのフォーカスを失うと自動で一時停止します。戻ったら「再開する」で再開します。

## 街と施設の歩行者

各人が通りや駅・会場の入口を出発点と目的地に持ちます。同方向、対向、入口付近を横断する移動が混ざり、初期位置・速度・到着と再入場の時刻はそろいません。初期配置はすでにその場所を歩いている状態です。

各人には一貫した急ぎ具合、希望速度、他人との距離、譲る強さ、立ち止まる習慣があります。急ぐ人は直接目的地へ、案内を読む人は側面の案内板で短く停止し、待ち合わせする人は待合で数秒待ってから進みます。向きと歩幅、速度、よけ方、停止によって違いが見えます。毎フレームのランダムな揺れはありません。

近い相手を見て減速と右側への回避を行い、速度への局所的な制約で体の重なりを防ぎます。止まっている人を押し動かしません。画面の外へ出た枠は、少し間をあけて外側の入口から次の通行人に再利用します。表示中の位置を飛ばして戻す処理はありません。入口が混んでいる間は新しい人を待たせます。各ステージの到着エリアでは目的に合わせた相手が待ち、近づくと場所に合わせた吹き出しが表示されます。吹き出しは通行エリアより上に置き、歩行者の進路を隠しません。この相手は通行人と別に扱い、接触ペナルティはありません。到着すると合流の結果を表示します。

## 開発とテスト

Canvas / CSS / JavaScript のみ。ゲーム用の外部依存パッケージ、外部通信、素材のダウンロードはありません。Node.js 18以上で、インストールなしに実行できます。

```sh
npm test
npm run build:pages
```

73件のテストで、移動・衝突・停止・目的地、群衆の再現性と個性、安全な初期配置、回避と停止、全ステージと追加配置での接触ゼロの経路、入力解除、公開用ファイルの限定とプロジェクト用URLを検証します。実ブラウザではタッチの同時押し・片方の解除、ステージ遷移・最終結果・歩行者の動きを確認しています。実際の端末でのタブ切替とスマホの操作感は、継続して確認する対象です。

- `crowd.js`：目的地と個性、シード付き配置、歩行・回避・停止。
- `traffic.js`：屋外の信号、方向別の横断経路、車・自転車の譲り、一団ごとの信号無視。
- `logic.js`：ステージ、プレイヤーの移動・接触・ゴール・時計。
- `input.js`：独立した入力元を扱う2ボタン状態。
- `game.js`：ブラウザの入力接続と描画。
- `art.js`：衝突判定に影響しないオリジナルの床・植栽・舞台の描画。
- `pose.js`：世界座標での実際の移動から向き・歩幅と、小さな横への傾きを計算。スクロールを本人の歩行に含めず、停止時は足を止めます。
- `character.js`：上は背中、下は正面、横・斜めは横顔を描き分ける人物描画。顔と頭は上下逆に回さず、靴と足運びを移動に合わせます。当たり判定は変えません。
- `branding.js`：画面タイトル「雑踏突破」。英語名は「Crowd Weave」です。
- `scripts/build-pages.js`：公開用ファイルのみを `_site/` に集めます。

静的な相対パスを使うため、GitHub Pagesの `/crowd-weave/` 配下でもCSS・モジュール・LICENSEが読み込まれます。

## GitHub Pagesへの公開手順

ソースコードのリポジトリは `monnouchi/crowd-weave` です。所有者が設定した標準の **pages build and deployment** により、mainへのpushを自動でビルド・公開します。既存のPages設定を使い、Sourceを変更する必要はありません。

1. `npm test` と `npm run build:pages` を確認し、承認した変更をmainへcommit・pushします。
2. Actionsの **pages build and deployment** が、そのコミットで成功したことを確認します。
3. 上の公開URLで開始画面・各ステージ・OGP画像・ライセンスを確認します。

`.github/workflows/pages.yml` は別方式の手動公開用です。現在の自動公開では実行しません。将来、所有者がSourceを **GitHub Actions** に変更した場合は **Publish GitHub Pages** を手動実行して `_site/` を配置できます。このワークフローはmainへのpushで自動起動しません。公式ActionsはコミットSHAに固定し、Pages書き込み権限は配置ジョブに限定しています。[GitHubの公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)に沿った構成です。

`npm run build:pages` の出力に含めるのは `index.html`、`style.css`、`game.js`、`crowd.js`、`input.js`、`logic.js`、`branding.js`、`pose.js`、`character.js`、`party.js`、`sound.js`、`share.js`、`tilt.js`、`traffic.js`、`art.js`、`og.png`、`LICENSE`、`.nojekyll` の18ファイルです。手動ワークフローはこの出力だけをアップロードします。現在のブランチ公開ではmainのルートがビルドの入力です。検証画像・ログ・ローカル確認用スクリプト・環境ファイル・秘密鍵・生成済み `_site/` はGit対象から除外しています。

## スマホの傾き操作（任意）

初期状態は左右ボタンです。「傾きで操作」を選ぶと、HTTPSの対応端末でのみセンサーを利用します。端末によってはこの操作時に許可を求めます。拒否・非対応・センサーの値が届かない場合は左右ボタンへ戻ります。センサーの値は端末内だけで使います。

スマホを楽な姿勢で持ってから開始し、左右に傾けると傾きの強さに応じて移動します。小さな揺れは無視し、動きを滑らかにしています。「正面合わせ」で基準の姿勢を取り直せます。専用の大きなブレーキは押している間だけ停止します。左右ボタンとキーボードも引き続き使えます。画面の向きを変えたり背景へ移ったりすると停止して入力を解除します。古いセンサー値では移動せず、値が戻らなければボタン操作へ戻して再開を待ちます。

許可の分岐とセンサーイベントは自動テストで模擬しています。実機の許可画面・センサー軸・感度・Safari/Chromeの操作感は、HTTPS公開後に実際のスマホで確認する必要があります。[MDNの許可API](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static)の条件に合わせています。

## 自宅からライブ会場への5ステージ

| ステージ | 場所                     | 目的                                     | 人数 |
| -------- | ------------------------ | ---------------------------------------- | ---- |
| 1        | 自宅から住宅街の角へ     | ひとりで出発して最初の友だちと合流       | 6    |
| 2        | 住宅街から最寄り駅へ     | 駅入口でもうひとりと合流                 | 12   |
| 3        | 駅のカフェ               | 合流し、郊外のライブ会場へ向かう         | 20   |
| 4        | 会場最寄り駅から会場前へ | 会場入口で友だちと合流                   | 30   |
| 5        | ライブ会場内のステージ前 | 前方の友だちのもとへ着き、ライブを楽しむ | 40   |

住宅・駅入口・カフェ・会場正面・ステージを描き分け、背景の人と混雑を増やします。短い導入、吹き出し、次の目的の予告、結果をこの旅に揃えています。列とトイレは駅・会場に置き、住宅街では花壇に変えています。駅間の移動はステージ間の物語として省略しています。合流ごとに仲間が1人増え、プレイヤーが実際に通った道をついてきます。自分と仲間の誰が接触してもタイムに加算され、同じ人への継続接触や複数人の同時接触は重複して加算しません。最後の仲間まで目的地に入ると到着になります。

BGMはステージごとに音型・テンポ・音色を変えています。通常の到着音もステージごとに少し変え、全5ステージの完走時は約2秒のファンファーレを鳴らします。到着音は1回だけ鳴り、再挑戦や次のステージ開始時は前の予約音を停止します。ミュート中は鳴りません。

場所別の人流：住宅街は近所のゆっくりした人とベンチでの滞在、駅は急ぐ人と縦方向の行き来、カフェは遅めの客と待合席・注文口付近の動き、会場前は同じ目的地の来場者グループ、会場内はゆっくり進む観客とドリンク・ロビーへの少数の横断です。共通のオリジナル音楽モチーフを、出発→駅のリズム→カフェの静けさ→会場への期待→パーティーの高揚へ編曲しています。

開始画面で「音ありで開始」「音なしで開始」を選べます。選択前は無音で、Enterの初期選択は「音なし」です。Tabで音ありを選んでEnterまたはSpaceでも開始できます。ステージ間で再度選ぶ必要はなく、再挑戦も現在の音設定を保ちます。ページを再読み込みすると無音の選択画面に戻ります。

仲間には番号と異なる服色を付け、接触した人を輪とメッセージで示します。両押しで止まると隊列が少し短くなり、止まりながら次のすきまを読めます。プレイヤーの画面位置は固定し、最後の仲間まで画面に収まるようにしています。先頭が着いても仲間の到着までは時計が進みます。

この版では仲間の追従・全員到着と、屋外の車・自転車・信号を実装しています。モデルでは40人＋仲間4人の3600更新を測り、経路記録の長さも検証します。端末実測FPSや初めて遊ぶ人の理解度をこの自動テストから推測してはいません。

PCの横幅850px以上では操作欄を横に並べ、480px幅のプレイ画面を表示します。開始時の案内は目的欄に表示し、接触通知は道路の外に置きます。結果では全員到着した状態と次の目的を示します。

## 屋外の横断歩道と接触ゼロチャレンジ

駅へ向かう住宅街（第2区間）と、会場最寄り駅から会場前への道（第4区間）に横断歩道があります。車と自転車は横の車道を通り、歩行者は横断歩道へ寄って信号を待ちます。住宅街の最初の角・駅カフェ・ライブ会場内に車は出ません。

信号は9秒周期で、赤2.5秒・青6.5秒です。仲間の人数と最大の隊列長から、全員が渡れる余裕時間を表示します。青の終わりには待つよう案内しますが、プレイヤーを信号の色だけで自動停止させません。自分で左右を両押しして停止線の手前で待ちます。青で進入してから赤へ変わっても違反にならず、最後の仲間が出るまで車を待たせます。接触で足が止まったり途中でブレーキをかけても、仲間を車に追い立てません。車は人がいる道路へ進入せず、すでに通過している車が横断歩道を抜けるまでは歩行者も待ちます。

信号は明るい赤と青緑の2灯と暗い消灯側を描き、矢印・停止記号・「進む／待つ」・残り秒数でも状態を示します。スマホの信号欄は14pxの文字と18pxの灯で表示します。赤で新たに横断を始めると「信号無視」として一団につき1回だけ2秒加算します。毎フレームや仲間の人数分は加算せず、正当な信号待ち・手動ブレーキでは加算しません。仲間がいれば1人が1度だけ道路の外の吹き出しで注意します。実際に車が横断歩道を通過中の場合は、車が抜けるまで進入を待ちます。車との衝突描写はありません。信号無視の回数は区間結果・合計結果・共有文章にも表示します。信号と車の時計は実時間ではなくゲームの進行時間で動くため、一時停止や背景への移動で進みません。接触の2秒加算で車が位置を飛ばすこともありません。

完走を基本目標にし、慣れたら「仲間全員で接触ゼロ」を目指せます。全5区間を無接触・信号無視なしで終えると結果に「すきまの名案内」を表示します。接触しても全員到着でき、結果は「みんなで最前列」です。両屋外区間の標準配置と追加シードでは、最後の仲間まで無接触・信号無視なしで到着する経路が、接触しながら直進する経路より速いことを検証しています。これは選んだ6配置での比較で、すべての操作を最適化した保証ではありません。

検証では全5区間と追加シードで、最後の仲間まで接触ゼロ・信号無視ゼロの到着を確認しています。車・自転車と全歩行者の非接触、歩行者同士の距離、信号の待機・余裕時間・途中停止による保護、停止からの復帰もテストします。ブラウザで全5区間、意図的に赤で待つ操作、青の表示、全員到着、2分停止してからの再開を確認しました。スマホ幅のブラウザによる確認で、実機センサーや初見の人による操作理解は継続確認の対象です。

## 表示・音・確認範囲

場所ごとの床、植栽、人物の細部と舞台をCanvasで描きます。演出は人の進路を隠さない領域へ置き、舞台の低コントラストの光は動きを減らす設定では固定します。プレイ中のカメラ・人物の当たり判定は演出で変えません。完走した後だけ、全員が揃った終幕用の構図を描きます。共有カードにも実際の完走画面を使い、タイム・接触・信号無視と合わせて表示します。

仲間が増えるほど、同じオリジナルの音型へ静かなパートが増えます。音を有効にするまでAudioContextを作らず、ミュート・停止・再挑戦で予約音を止めます。音がなくても信号・接触・到着・隊列の状態は表示で分かります。

開始画面は道路を進めず、音の有無を選べます。短いスマホ画面でも開始と結果のボタンを押せる配置を確認しています。320×568、375×667、390×844、640×360、844×390、1165×747のブラウザーで確認しました。左右のボタンは小さい画面の下端に余白を取り、横方向のはみ出しを防ぎます。

このMacのブラウザーで、雨の30人＋仲間3人の更新・Canvas描画命令・画面表示更新のCPU時間は平均約0.95ms、95%点約1.2ms、最終場面の40人＋仲間4人では平均約1.01ms、95%点約1.4msでした。擬似時計で再現したフレームを実CPU時計で測った値です。GPU描画のFPSや実際のスマホの性能を示す値ではありません。センサーの実機動作・Safari/Chromeの操作感・初見の理解度は、人が実機で確認する対象として残しています。

描画用Canvasは端末のピクセル密度に合わせて最大2倍の解像度にし、論理座標・当たり判定・操作感は480×680のままにします。共有カードの切り抜きも描画解像度に合わせます。

スマホの横向きでは操作欄を道路の横に置き、短い縦寸法でも道路を極端に縮めない配置にしています。傾き操作中の向き変更は時計を止めて正面合わせを待ちます。

## 信号前の滞留と雨

北向きと南向きの通行人は進行方向ごとの位置へ寄ってから横断し、赤で前進を止めても横へ列を整えられます。屋外の身体間隔は中心間32pxを目標に速度を調整し、列の間にプレイヤーと仲間が通れるすきまを保ちます。人数・本来の目的地・集団は維持します。2区間×3シードを55秒ずつ測り、停止線での経路、身体の間隔、両方向の列の解消を検証しています。

ステージ4だけが雨の会場前です。傘を持つ人と、傘がなく少し速く入口へ向かう人を描き分け、一部の人は近い軒下で短く雨宿りしてから元の目的地へ進みます。集団内の傘と速度はそろえ、既存の家族や施設の列は維持します。雨は通路外の側面に描き、頭・足・信号・中央のすきまに雨粒や暗い幕を重ねません。強い点滅・雷はなく、動きを減らす設定では雨粒も静止します。
