# ライブへ行こう！ / Crowd Weave

人の流れとすきまを読み、仲間全員をライブ最前列へ導くブラウザゲームです。自動で前進し、左右でよけ、両押しで立ち止まります。Canvasと標準Web APIだけで動作し、インストールは不要です。

公開版は [GitHub Pages](https://monnouchi.github.io/crowd-weave/) にあります。ローカルでも以下の手順で起動できます。

この資料は実装仕様・開発検証用です。遊び方は[ユーザーマニュアル](../README.md)を参照してください。

## 起動と操作

Python 3 があれば、リポジトリで `python3 -m http.server 4175 --bind 127.0.0.1` を実行し、http://localhost:4175 を開きます。Node.js がある場合は `npm start` でも起動できます。

- PC：← / → または A / D。両方を押すと停止します。Enterで開始・次の区間・再開・完走後の再挑戦。長押しEnterで複数の区間を飛ばしません。Escapeで一時停止。
- スマホ：左右のボタンを押して移動し、両押しで停止。片方を離すと残った方向へ進みます。「操作ガイド・設定」で任意の傾き操作を選べます。
- ブレーキ中も通行人は動きます。一時停止・背景移動では人・信号・到着タイムも停止します。再開はボタンで行います。
- 接触は＋2秒、0.35秒停止。1.4秒の猶予と、同じ人との連続接触を重複加算しない仕組みがあります。信号無視は横断開始時に＋2秒、横断ごとに1回です。押す・傷つける操作はありません。
- 音は開始時に選べます。途中の「音：ON/OFF」でも切り替えられます。結果では画像保存・対応端末の標準共有・文章コピーを使えます。自動投稿や外部への送信は行いません。

指はそれぞれ独立した入力を所有します。ボタン外の解放、pointercancel、lostpointercapture、touchend/cancel、停止・再開・背景復帰で後始末します。ボタンのキャプチャが使えない場合も、画面全体の解放イベントで解除します。正当な長押しに制限時間はありません。操作中はページの選択・長押しコールアウトを抑え、実際の選択中断では一時停止します。操作していないときの説明・結果の文章は選択・コピーできます。

## 5区間の旅

| 区間 | 場所と流れ                                           | 通行人数 / 仲間 | 先頭の縦距離 | 前進のみの基準時間 |
| ---- | ---------------------------------------------------- | --------------- | ------------ | ------------------ |
| 1    | 自宅から住宅街の角へ                                 | 6 / 0           | 540px        | 7.2秒              |
| 2    | 住宅街から駅入口へ。信号を見て横断                   | 12 / 1          | 540px        | 7.2秒              |
| 3    | 左右に行き交う駅構内通路を渡り、奥の壁沿いのカフェへ | 20 / 2          | 540px        | 7.2秒              |
| 4    | 雨の駅前→4車線の大通り→公園の小道→郊外の会場前       | 30 / 3          | 1040px       | 13.9秒             |
| 5    | ロビー→チケット受付→重厚な扉→暗いホール→最前列       | 40 / 4          | 860px        | 11.5秒             |

基準時間は縦距離÷75px/秒で、信号待ち・回避・接触加算・全員の合流待ちを含みません。最初の3区間の距離は維持し、4・5だけを具体的な道中・入場シーンに合わせて延長しました。最後の仲間が到着するまで結果に進みません。仲間はプレイヤーの実際の経路を歩き、ブレーキで列を整えられます。

最終区間の観客は上向きを主とし、舞台に近づくほど密度が上がります。一部は到着後に立ち止まって鑑賞し、ゆっくりサイリウムを振ります。受付はチケットを持つ係員と机・ゲートで示し、中央を歩いて通ると確認が完了します。別の操作ボタンはありません。観客は中央も含む床全体に間隔を保って配置し、鑑賞→近くの位置への移動→再鑑賞を数回繰り返してから後方左右の出入口へ戻ります。再入場も後方からで、舞台からは出現しません。鑑賞時間をずらし、前方の密度を維持しながら隙間が変化します。移動する人と鑑賞中の人のすきまを選び、左右とブレーキで仲間を導きます。

## 横断歩道と雨

区間2には1か所、区間4には独立した2か所の横断歩道があります。駅前の大通りは4車線・幅145px、公園側は2車線・幅65pxです。車・自転車は一般の歩行者や、青で渡り始めた仲間列を待ちます。信号は固定のゲーム時計で動き、プレイヤーへの反応で赤にはしません。

2車線は赤2.5秒・青6.5秒、4車線は赤2.5秒・青9秒です。初期位相をずらし、標準的な最初の到達時に赤を見て短く停止する判断が生まれるようにしています。青で合法に入った仲間列は、途中で赤になっても最後尾まで保護されます。正当なブレーキ停止は減点しません。赤信号や通過中の車両が自動でブレーキをかけることはありません。赤での進入は＋2秒で、車・自転車が自分や仲間の身体に触れると即ゲームオーバーになり、その区間から再挑戦できます。横断歩道の外の進入位置は道路の形に合わせて制限します。

区間4だけが雨です。傘を持つ人、傘のない人、一部の雨宿りを描き分けます。傘は肩から腕・握る手・柄・骨へつながり、8方向で前後の重なりを変えます。歩行時の揺れは小さく、顔と進路を読めるようにしています。雨粒は側面に置き、強い点滅や雷はありません。

## 人物・空間・音

外見には髪型、服、体格、肌の色、子どもや年配の人の幅を持たせています。外見から国籍や民族を設定しません。旅行者は荷物や地図で示します。外見の差は目的・速度の分類と独立しており、描画は当たり判定を変えません。プレイヤーは青い服・足元の柔らかい光とYOU、仲間は服色と番号、待ち人・受付係は位置・手の動作・帽子で見分けられます。合流前後で同じ人物の外見を保ちます。

区間1〜4は店の壁・窓や厚い植栽で中央の合流口を残します。最終区間は舞台と平行な一列の柵が両側の壁につながり、客席の広い前列へ到着します。仲間は選んだ到着位置の近くに集まり、一般の観客と同じ客席で鑑賞します。境界の奥には街や施設を描き、到着点の先が空白にならない構図です。

音はオリジナルのWeb Audio合成です。最終区間は120BPMのドラム、ベース、裏拍を含むリズムを使い、音量を上げるだけで曲調を変えません。区間1〜4は旋律を2オクターブ上げ、一定の拍で長めに鳴らします。扉の外は通常の0.65倍と2.4kHzのフィルターで、入場前でも拍が聴こえるようにし、入場時に約0.35秒で通常音量と控えめな左右の広がりへ移ります。通常音量を超える増幅はありません。効果音は音楽の空間フィルターと分け、各到着はG majorのI–V–Iによる専用曲、最終ゴールはドラム・ベース・和音を伴う約10秒の専用曲です。移動曲を止めて切り替え、ミュート・背景停止・再挑戦で予約済みの音も止めます。

暗いホールのスポットライトは人物の下に描き、輪郭やすきまを黒く塗りつぶしません。強い点滅はなく、端末の「動きを減らす」設定で雨・光・足の動き・小物の揺れを止めます。表示用Canvasは画面全体を使い、最大2倍の解像度にします。スマホの可変高さ・安全領域を考慮し、HUDとボタンの間に前方500単位と後方180単位を保ちます。横長画面ではHUDとボタンを中央の道の左右に置きます。余った領域は建物・ホールの壁で埋め、論理座標の幅480pxと当たり判定は一定です。OSの全画面モードは要求しません。人物は首・胴・つながる腕・脚を描き分け、足の着地と向きを保ちます。信号は縦の赤/青の灯器と停止/歩行の形を併用します。

## 傾き操作

初期状態は左右ボタンです。HTTPSの対応端末で「傾きで操作」を選ぶと、必要な場合だけ許可を求めます。拒否・非対応・値が届かない場合はボタンへ戻ります。「正面合わせ」で基準を取り直せ、専用ブレーキは押している間停止します。画面の向きや背景が変わると停止して入力を解除します。センサーの値を端末外に送りません。

## 検証

`npm test` はNode標準のテストランナーを使います。入力の指ごとの所有、長押し、キーボード、信号と2横断の独立判定、車と全員の身体間隔、ゴール境界、合流待ち、描画の向き、雨、音・共有・公開ファイルの除外を確認します。`node validation/backport-check.js` は最終区間の6シードを88秒間観察し、中央・前方密度、後方からの循環、舞台から出現しないことを確認します。複数シードで実際の全員の経路を探索し、接触・信号無視ゼロで到着することを再実行します。

ブラウザーではネイティブの複数タッチ、12秒の両押し、片指の解除、ボタン外解放、取消、キャプチャ喪失、選択中断、背景復帰、説明のコピーを確認しています。通常の描画フレームでも開始→5区間すべての無接触到着→最終結果→再挑戦を確認しました。320×568、390×844、640×360、844×390、PC表示で景観と操作欄、仲間の実際の頭上につながる1回の吹き出しを確認しています。

iPhone/Safariなど実機で報告された入力症状は、このMacのChromiumで実機再現したとは扱っていません。キャプチャ不在時のボタン外解放漏れは模擬ケースで再現・修正済みです。実機の長押しメニュー、タッチイベント順序、傾きの感度、音の聴こえ方と操作感は継続確認の対象です。

## 構成と公開

- `logic.js` / `party.js`：区間の座標・進行・接触・仲間と全員到着。
- `crowd.js`：固定シードの目的地、局所回避、ライブ観客の配置と鑑賞。
- `traffic.js`：各横断の信号時計、車、仲間列の保護、違反。
- `input.js` / `tilt.js`：指・キーボード・傾き入力と中断時の解除。
- `game.js` / `character.js` / `pose.js` / `art.js`：画面、人物の8方向と歩行、景観と吹き出し。
- `sound.js` / `share.js` / `branding.js`：音、結果カード、名称。

`npm run build:pages` は許可リストの17ファイルと `.nojekyll` だけを `_site/` へコピーします。検証用スクリプト・画像・ログ・環境ファイル・秘密鍵・生成済み `_site/` は公開物から除外します。`og.png` はオリジナルの1200×630の静的OGP画像です。

リポジトリは `monnouchi/crowd-weave` です。所有者が設定した標準の **pages build and deployment** はmainへのpushで自動公開します。公開が承認された際はテスト・ビルド確認後にcommit・pushし、該当コミットのActions成功と公開URLを確認してください。`.github/workflows/pages.yml` は別方式の手動公開用で、現在のブランチ公開では使いません。
